# МКГиК: многопользовательский Worker

Статус: разработка в отдельной ветке. Старый `bot.py` и утренний workflow продолжают работать. Этот каталог — настоящий обработчик Telegram webhook, диалоги и планировщик с D1, а не макет. Код не включает публичные учебные фикстуры в рабочую сборку.

## Что реализовано

- Только личные чаты; повторный `/start` сохраняет подписку.
- Каталог настоящих групп с `/groups`, поиск, страницы по 8 результатов, независимые черновики и подтверждение сохранения.
- Обе подгруппы/1/2; общегрупповые занятия всегда включаются.
- Сегодня, завтра, текущая/следующая пара, неделя, моя группа, настройки, просмотр другой группы без смены подписки.
- Утреннее время 06:00, 06:30, 07:00, 07:30 либо своё ЧЧ:ММ; отключение утренней рассылки; явный выбор напоминаний за 5/10/15/30 минут.
- Изменение настроек аннулирует будущие задания старой подписки. Пауза до московской полуночи завтра и подтверждённое удаление настроек.
- Кеш на группу и дату; отдельные состояния confirmed/unpublished/network_error/invalid. Отсутствие надёжных данных не объявляется выходным. Полностью пустая будущая неделя считается ещё не опубликованной консервативно.
- Устойчивые задания, уникальные ключи, попытки доставки, leases, защита от дублей update_id и cron, отложенный повтор при 429, остановка при 403. При неясном результате сети состояние `uncertain`: автоматического повторения нет; exactly-once не обещается.
- Просроченные напоминания не отправляются. При задержке до начала рассчитывается фактически оставшееся время. Отмена/перенос/смена кабинета подтверждённым источником пересчитывают задания.
- В тихий день не будит, если пользователь не включил отправку в дни без занятий.
- Экранирование HTML и разбиение длинных ответов без разрыва сущностей/тегов.

Основные функции не вызывают Groq и работают при его отсутствии. Свободные вопросы, вечерняя рассылка, «пора выходить» и отдельные сообщения «было → стало» пока не включены; это следующий этап после основной версии.

## Бесплатный пилот, не обещание масштаба колледжа

Регистрация ограничена 50 подписками. Cron каждую минуту ставит один служебный тик в Cloudflare Queues Free. Диспетчер ставит отдельные ограниченные задания только для наступивших событий: планирование одного пользователя, доставка максимум трёх сообщений или обновление максимум одной группы за вызов consumer. Это отдельные queue invocations, а не самовызовы через service binding с предположением о сбросе лимитов.

Queues Free: 10 000 операций/сутки. В норме запись/чтение/удаление одного короткого сообщения требуют 3 операций. Код ограничивает постановку 2800 сообщений/UTC-сутки (~8400 операций без повторов), фоновые работы останавливает раньше (2400), оставляя запас для тиков и доставки. При расходовании бюджета или задержках очереди часть уведомлений может быть пропущена; это нужно отслеживать на пилоте. Очередь не подключает платный тариф.

Глобальная отправка Telegram ограничена 25 сообщениями/секунду и одним сообщением/секунду в чат. Большой пик распределяется между минутами. D1 имеет индексы по времени заданий, группе, пользователю и состоянию. Кеш и журнал общие для экземпляров Worker. Утренний сценарий 50 подписок в двух группах проверяется локально; это не проверка всего колледжа со всеми 33 группами и не подтверждение удалённого billable CPU.

Локальные тесты не измеряют реальный billable CPU на Cloudflare. До выпуска нужно проверить CPU (<10 мс), D1 rows read/written, количество запросов в каждом обработчике и минутные bursts на закрытом staging. Если CPU/бюджет не укладываются, публичный режим не включать: уменьшить партии или изменить архитектуру, а не подключать оплату.

## Настройка с телефона

Войти в Cloudflare (Free) и убедиться, что Workers платный план не включён. Для GitHub deployment требуется Cloudflare API token с Workers Scripts Edit, D1 Edit и Queues Edit только в выбранном аккаунте. Не присылай токен в чат.

В GitHub Settings → Secrets and variables → Actions добавь:

- `CLOUDFLARE_API_TOKEN` — ограниченный токен;
- `CLOUDFLARE_ACCOUNT_ID` — ID аккаунта;
- `WEBHOOK_SECRET` — случайная строка A–Z/a–z/0–9/underscore/hyphen;
- `ADMIN_SECRET` — другая длинная случайная строка.

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `GROQ_API_KEY` уже существующего бота остаются в Secrets. В новой версии `TELEGRAM_CHAT_ID` используется только как адрес владельца для закрытых тестов, а студенты хранятся в D1.

После проверки Free добавить переменную `FREE_PLAN_CONFIRMED=true`. После проверки и включения staging workflow в основной ветке запустить `Worker v2 staging deploy`. Добавление staging workflow не отключает старую рассылку; переключение выполняется отдельно. Скрипт создаёт одну D1, применяет миграцию, создаёт одну очередь Queues Free, выкладывает закрытый Worker, сохраняет токены в secrets Cloudflare, проверяет реальный источник и отправляет настоящее расписание только владельцу. Старый webhook и Actions не переключаются.

## Контролируемое переключение (после staging)

1. Проверить `/ops/probe`, живой ответ Telegram `ok=true`, heartbeat `/ops/status`, CPU и квоты Cloudflare.
2. Задать webhook на HTTPS `/telegram` с `secret_token=WEBHOOK_SECRET`, `allowed_updates=["message","callback_query"]`, `max_connections=4`. Публичный режим пока выключен; проверить диалоги владельца.
3. Убедиться, что настройки владельца сохранены в D1 и соответствуют его выбору.
4. Остановить расписание старого Actions только непосредственно перед включением нового планировщика. Исключить уже выполняющийся старый запуск.
5. Включить `DELIVERY_ENABLED=true`, проверить следующее настоящее событие владельца и затем открыть пилот (до 50 студентов). Не отправлять студентам синтетические пары.

Если проверка не прошла: оставить `DELIVERY_ENABLED=false`, удалить webhook через Telegram API без уничтожения ожидающих обновлений и вернуть старый Actions. D1 не удалять: это сохраняет настройки и историю для безопасного повторного запуска. Не включать одновременно две утренние рассылки.

## Тесты

```sh
cd worker
npm ci
npm test
npm run check
npx wrangler deploy --dry-run
```

Тестовая точка входа `test/entry.mjs` работает только локально; рабочая точка входа строго `src/index.mjs`. Fake Telegram и два синтетических пользователя тестов не являются живой доставкой. В D1 сохраняются только ID чата/пользователя, настройки и служебные данные; имена, телефон и геолокация не запрашиваются. Содержимое текстовых updates очищается после обработки. Логи пользовательских сообщений/ID и секретов не печатаются. Ответы `/ops/*` защищены `ADMIN_SECRET` и не содержат персональных данных.

## Общий доступ

Ручной workflow `Worker v2 public switch` использует `scripts/activate-public.mjs`: сначала проверяет реальный источник, существующие D1/Queues и выполнение Cron; затем отключает старый `schedule.yml`, развёртывает `DELIVERY_ENABLED=true`, проверяет webhook и планировщик и отправляет проверочное настоящее расписание только владельцу. Если переключение не подтверждено, возвращает закрытый режим и старый workflow. При неопределённой отправке владельцу автоматического повторения нет. Настройки в D1 не сбрасываются. Начальная ёмкость остаётся 50 подписок; доступ к диалогам больше не ограничен владельцем. Полная нагрузка колледжа не проверена.
