# Расписание ЗУ-41/23 в Telegram

Каждое утро в 07:07 по Москве GitHub Actions получает расписание из [официальной страницы группы](https://site.mstimetables.ru/01a011c0a5b475b38b2f1e82c13ccb26/groups/63).

В сообщении сохраняются время, предметы, преподаватели, кабинеты и обе подгруппы. Поля читаются из HTML по отдельности. При отсутствии даты, неизвестной структуре или ошибке сайта бот отправляет предупреждение; отсутствие данных не объявляется выходным. «Занятий нет» допустимо только при явной отметке сайта.

Groq используется только для выбора дополнительной краткой сводки из проверенных фактов. Его отсутствие, таймаут, ошибка или неподтверждённый ответ не препятствуют отправке основного расписания.

## Настройка с телефона

В репозитории открой Settings → Secrets and variables → Actions → New repository secret. Создай:

- `TELEGRAM_BOT_TOKEN` — токен бота из BotFather;
- `TELEGRAM_CHAT_ID` — числовой ID получателя или группы;
- `GROQ_API_KEY` — ключ Groq (необязателен для отправки расписания).

В личном чате с ботом предварительно нажми Start или отправь `/start`. Для группы добавь бота и разреши отправку сообщений.

После сохранения Secrets: Actions → MKGiK ZU-41 morning schedule → Run workflow → Run workflow.

Подтверждение доставки: в шаге Send Telegram schedule должна появиться строка `Telegram API: ok=true; message_id=...`. Успешные тесты или зелёный шаг установки зависимостей сами по себе не подтверждают доставку.

## Ежедневный запуск и стоимость

Workflow запускается один раз в день на стандартном Linux runner; максимум 3 минуты. Установка браузера не требуется. Публичный репозиторий использует бесплатные стандартные GitHub-hosted runners; платные ресурсы не включаются. Время планового запуска приблизительное: GitHub может задерживать задания. После 60 дней без активности GitHub может отключить плановые задания публичного репозитория; при необходимости снова включи workflow в Actions.

## Проверка локально

```sh
python -m pip install -r requirements.txt
python -m unittest -v
python bot.py --dry-run
```

`--dry-run` получает реальное расписание и не отправляет сообщения. Для рабочего запуска ключи должны поступать через переменные окружения. Никогда не добавляй `.env` в Git.

Переменная репозитория `SUBGROUP` может быть пустой (обе подгруппы), `1` или `2`.
