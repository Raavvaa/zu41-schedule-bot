Основной бот расписания, main, рабочая D1, webhook и ветка деплоя не изменены.
Новых зависимостей и миграций нет. Автопроведение не включается.

## Что делает изменение

- Выбор текстовой модели через `CHAT_PROVIDER`: `groq` (по умолчанию) или `openrouter`.
- При OpenRouter используются отдельный секрет `OPENROUTER_API_KEY` и модель
  `OPENROUTER_MODEL` (по умолчанию `openrouter/free`). Допускаются только этот
  бесплатный маршрутизатор или идентификатор `provider/model:free`. Платный ID
  отклоняется до запроса. Автоматического переключения сервисов нет.
- Инструменты, проверка сумм, подтверждение и идемпотентность остаются прежними.
  Приветствие, рассказ, воспоминание и мнение могут получать обычный текстовый ответ.
- Фиксированные адреса API; редиректы не выполняются. Секрет не попадает в сообщения модели.
- OpenRouter получает `require_parameters: true`, `data_collection: deny`.
  Если подходящий бесплатный провайдер недоступен, запрос завершается ошибкой;
  политика не ослабляется автоматически.
- Локальный бюджет OpenRouter — 50 попыток обращения за день по UTC+3,
  включая дополнительные раунды инструментов. Это ограничение приложения,
  не обещание доступной квоты провайдера. Groq сохраняет бюджет 200.
- Аудио по-прежнему распознаётся через Groq. Одного ключа OpenRouter недостаточно
  для голосовых; существующий `GROQ_API_KEY` нужно сохранить.
- `/health` сообщает `chat_provider` и SHA. Это не проверка действительности ключа.

## Перед включением

1. Отозвать ключ, опубликованный в переписке, в https://openrouter.ai/settings/keys .
   Новый ключ не отправлять в чат, не вставлять в git или wrangler.jsonc.
2. В настройках именно Worker `brat-sabunchi-accountant` сохранить новый ключ как
   **secret** `OPENROUTER_API_KEY`. Обычные переменные: `CHAT_PROVIDER=openrouter`,
   `OPENROUTER_MODEL=openrouter/free`.
3. Сначала выполнить проверки ниже. При выпуске проверить сохранность всех прежних
   секретов, DB binding, Cron и настроек. Не заменять рабочую конфигурацию файлом
   wrangler.jsonc из репозитория: там тестовый ID базы и `ENABLED=false`.
4. Секрет GitHub Actions нужен отдельно, только если ручной smoke запускается в CI.
   Создание GitHub secret само по себе не создаёт секрет Cloudflare Worker.
5. Выпускать проверенный SHA этой новой ветки через предназначенный бухгалтеру
   процесс обновления существующего Worker. Workflow worker-cache.yml в feature/main
   относится к другому проекту — не запускать. Подготовленная ранее deploy-ветка
   закреплена на старом SHA и не включает это подключение автоматически.
6. После выпуска сверить `/health`: ожидаемый SHA, `enabled=true`,
   `chat_provider=openrouter`. Отдельно проверить обычный разговор и подтверждение
   предложения. Рабочую D1 не использовать для синтетических тестовых проводок.

В текущей сессии выпуск не выполнен: доступ к запуску Actions через браузер
заблокирован разрешениями среды, а подключённый GitHub-инструмент не поддерживает
workflow_dispatch. Обход этого ограничения не выполнялся.

## Проверки без внешних API

Из папки accountant:

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run test:openrouter
```

`test:openrouter` запускает те же диалоговые сценарии с поддельным OpenRouter,
временной D1 и поддельным Telegram. Проверяется отсутствие записи при рассказе,
вопросе о прошлом и мнении, корректность подтверждений, ошибок и лимита запросов.
Это проверка интеграции и защит, а не доказательство качества живой модели.

## Один ручной smoke с живой моделью

Ключ должен уже находиться в защищённой переменной окружения. Не передавать его
литералом в командной строке и не выводить окружение.

```sh
CHAT_PROVIDER=openrouter OPENROUTER_MODEL=openrouter/free node test/conversation-live.mjs --opinion
```

Максимум 8 HTTP-запросов к выбранной модели, остановка на первой ошибке,
временная база и вымышленные данные; сетевых вызовов Telegram нет.
Обычный запуск без `--opinion` проверяет рассказ о подарке, память и последующую
явную запись. Каждый запуск расходует общую квоту аккаунта; не запускать на каждый push.

## Ограничения и откат

Бесплатный маршрутизатор выбирает доступную модель, поэтому качество и модель
могут меняться. Бесплатность не означает отсутствие 429 или стабильную задержку.
Перед закреплением конкретной `:free` модели нужна отдельная проверка её tool calling.
При включении диалог и контекст учёта передаются OpenRouter и выбранному провайдеру;
`data_collection: deny` ограничивает выбор провайдера, но не отменяет саму передачу.

Откат конфигурации: `CHAT_PROVIDER=groq`, если сохранён действующий Groq-секрет.
Откат кода: предыдущий проверенный SHA. Схема базы не менялась. Ключ, однажды
раскрытый в чате, не восстанавливать при откате.

Официальные материалы:
- https://openrouter.ai/openrouter/free
- https://openrouter.ai/docs/guides/routing/provider-selection
- https://openrouter.ai/docs/api-reference/limits
