# Панда — личный Telegram-помощник

Отдельный Worker: `panda-personal-agent`. D1 привязана к личности бота: `panda-personal-agent-<bot_id>`. При смене бота старая база сохраняется отдельно, её очередь не переносится. Официальный Bot API и Chat Automation. Полная сессия аккаунта не используется. Бухгалтер и бот расписания не меняются.

## Подключение с телефона

1. Открой созданного бота и нажми **Start**.
2. В `@BotFather` выбери этого бота → **Bot Settings → Business Mode → Enable** (название пункта может быть Chat Automation/Secretary Mode в новом клиенте).
3. На iPhone: Telegram → **Настройки → Изменить профиль → Автоматизация чатов**: введи имя бота без `@`, выбери Панду и только нужные личные чаты. Разреши ответы. Разрешение менять фото нужно только для смены аватара.
4. Для автоответов напиши в выбранном чате **«панда, отвечай на все сообщения этого чата»** или **«панда, отвечай здесь»**. Явная команда владельца включает этот чат сразу на 2 часа, без модели и повторного подтверждения. Результат приходит в личку с Пандой. Команду в чате видит собеседник. Для черновиков используй **«панда, помогай здесь»** и кнопку в личке; альтернативный выбор чата — `/chats`.
5. Автоответы можно включать через `/chats` или задавать другие параметры просьбой с подтверждением, на срок до 12 часов. Повтор прямой команды продлевает авто на 2 часа. `/stop` в личке останавливает всё; **«панда, стоп»** в чате — только этот чат. В управляющей личке команда без конкретного адресата открывает выбор чата.

Перед включением текста чужого чата требуется согласие участников на обработку контекста Groq/SiliconFlow/OpenRouter. До включения сохраняются только технические сведения о чате, без его текста. Голосовые не скачиваются и не распознаются.

## Что работает

- Обычный разговор с владельцем и поручения на естественном языке.
- «Запомни…», «Что помнишь…», «Забудь…»: постоянные факты с источником, раздельно по чату. По просьбе владельца сохраняются явные заметки; фоновое извлечение сохраняет только проверенные по исходному сообщению цитаты с авторством.
- Черновики и ограниченные по времени автоответы в выбранных личных чатах; новые обязательства, неизвестные личные факты и чувствительные темы модель должна отдавать на проверку владельцу. Это семантическая оценка модели, а не гарантия идеального понимания.
- Стиль по ручным исходящим текстам за 72 часа. Сообщения, написанные ботом, не обучают стиль. При малом числе примеров — нейтральный тон.
- Разовая отправка сообщения, пост в подключённый канал и смена фото профиля: точный предпросмотр и кнопка владельца. Для канала бот добавляется администратором, а права владельца проверяются перед публикацией.
- `/start`, `/help`, `/chats`, `/status`, `/memory`, `/stop` работают без модели.
- Ручной ответ владельца отменяет устаревший подготовленный ответ, но не блокирует следующие входящие на 10 минут. Новое входящее очищает паузу, оставленную старой версией. Стоп и истечение срока автоответов по-прежнему запрещают отправку. Серия уже накопившихся сообщений объединяется.

## История и память

Bot API не выдаёт архив до подключения. Чтобы сразу взять стиль из последних трёх дней, можно вручную экспортировать один чат из Telegram Desktop в JSON, без медиа. После включения чата отправить файл до 1 МБ Пандe с подписью `/import <код чата из /chats>`. Импорт берёт только исходящие тексты владельца за 72 часа и сверяет чат. Чужой текст и голосовые из экспорта не используются.

Недавние сообщения: 72 часа, очистка ежечасная. Факты: до удаления владельцем, максимум 50 на область. Краткое резюме чата сохраняется между сообщениями; команда «забудь» очищает также краткий контекст области. Обработанный inbox хранит только ключи, без текста. Payload завершённых отправок/предложений очищается через сутки; неизвестный результат сохраняется для разбора. Технический журнал без текстов — 30 дней. Для полного удаления из провайдерских логов действуют отдельные правила соответствующего API.

## Модели и отказы

Groq `openai/gpt-oss-120b` → SiliconFlow `Qwen/Qwen2.5-7B-Instruct` → OpenRouter `openrouter/free`. Ключи в Secrets. Раздельные суточные бюджеты: Groq 200000 токенов / 500 запросов; SiliconFlow 500000 / 1000; OpenRouter 50000 / 100. Значения задаются переменными `<PROVIDER>_DAILY_TOKENS` и `<PROVIDER>_DAILY_REQUESTS`. Сутки UTC. Считаются попытки fallback и эмбеддинги; внутренние лимиты не являются тарифными квотами провайдера. Стоп, статус, очередь и права не зависят от LLM.

При недоступности всех провайдеров собеседнику ничего не отправляется; владелец получает уведомление. Старые ответы автоматически позже не рассылаются. Никаких чужих ключей, массовых регистраций или платного переключения.

## Доставка

D1 inbox/outbox, один обработчик с арендой блокировки. Повторные события и нажатия не создают повторные действия. Отправка подтверждается возвращённым Telegram `message_id`. При сетевой неопределённости или падении во время send статус **unknown**, автоматического повтора нет. Явный Telegram 429 повторяется после `retry_after`, пока ответ актуален. Exactly-once Bot API не обещает. Изменение чата/стоп после начала сетевой отправки не может отозвать уже отправленный запрос.

## Проверка и выкладка

```sh
npm ci --prefix panda
npm run check --prefix panda
npm test --prefix panda
npm run live --prefix panda
```

Тесты используют Miniflare и вымышленные данные. Live: временная D1, максимум 6 HTTP-запросов к моделям, 0 к Telegram; сценарии разговора, памяти и согласования обязательств. Деплой дополнительно делает один синтетический probe модели (до двух провайдеров) и `/start` только владельцу. Реальный автоответ собеседнику проверяется после добровольного подключения чата.

Ветка `feat/panda-agent-20261110`, ручной workflow `.github/workflows/worker-cache.yml` **в этой ветке**. В main ничего не меняется. Workflow принимает только эту ветку; разворачивает только `panda-personal-agent`. Рабочий токен берётся из `PANDA_REPLACEMENT_BOT_TOKEN`, личность проверяется по `EXPECTED_PANDA_BOT_ID`. Прежний `PANDA_BOT_TOKEN` используется только для отключения старого webhook, если он указывает на этот же Worker. Секреты бухгалтера и бота расписания не используются. Cloudflare Free подтверждается существующей переменной `FREE_PLAN_CONFIRMED=true`.

Если проверка активированной версии не проходит, скрипт отключает только Панду. Обычная остановка — `/stop`; аварийная — отключить подключение в Telegram и `ENABLED=false` для Worker. Откат — проверенный предыдущий deployment Panda в Cloudflare; схема этой версии аддитивная. Не откатывать другие Workers.

## Проверка подключений

Если событие `business_connection` было пропущено, первое новое сообщение подключённого чата восстанавливает связь через `getBusinessConnection`. До записи проверяются ID связи, ID владельца и активность. Сохранённое отключение имеет приоритет над поздним событием или ответом проверки.

`панда, помогай здесь` создаёт карточку черновиков без модели. В управляющей личке та же команда открывает список чатов. `/chats @имя` также открывает список известных чатов без модели: произвольную личную переписку по имени Bot API не открывает. `/status` различает подключение профиля и поступление сообщений чатов.

В workflow можно выбрать `operation=diagnose`: только getMe/getWebhookInfo/getBusinessConnection и SELECT метаданных D1. Помимо доставки, проверяются глобальная остановка, срок режима, ручная пауза, окно ответа и расход запросов/токенов. В журнал не попадают тексты, ключи и идентификаторы владельца/собеседников. `operation=deploy` остаётся штатным выпуском.

## Непрерывность диалога

Модель получает последнюю реплику отдельно от истории и недавние отправленные ответы. Повтор ответа или новое приветствие в уже начатом разговоре исправляется одной дополнительной генерацией, затем блокируется, если повтор сохранился. Перед автоматической отправкой действует дополнительная проверка очереди. Проверка ограничена текущим чатом и последними 30 минутами.

В auto обычное приветствие не требует подтверждения. Лимит — 6 автоматических ответов за минуту; превышение даёт одно уведомление владельцу, а не карточки «Выполнить». Черновики и новые обязательства сохраняют отдельную проверку владельцем. Редактирование входящего обновляет контекст, но не запускает новый ответ. Повтор одной message_id с другой update_id не запускает повторную генерацию.

Живой тест использует вымышленные данные и временную базу: три последовательных реплики, проверка повторов и лишних подтверждений. Telegram в этом тесте подменён локальной функцией; реальным собеседникам тестовые сообщения не отправляются.

## SiliconFlow

Ключ хранится только в `SILICONFLOW_API_KEY`. Международный базовый URL:
`SILICONFLOW_BASE_URL=https://api.siliconflow.com/v1`.
Дефолты: `SILICONFLOW_CHAT_MODEL=Qwen/Qwen2.5-7B-Instruct`,
`SILICONFLOW_EMBED_MODEL=BAAI/bge-m3`. Доступность зависит от аккаунта:

```sh
curl -s -H "Authorization: Bearer $SILICONFLOW_API_KEY" https://api.siliconflow.com/v1/models
```

Проверка 10 ноября 2026: чат-модель доступна и ответила HTTP 200;
`BAAI/bge-m3` отсутствует в каталоге проверенного ключа, embeddings вернул HTTP 400.
При таком отказе память автоматически использует текстовый поиск.
Это установленная причина нового SiliconFlow 400, не диагноз исторических Groq/OpenRouter 400/404.
Диагностика при переданном ключе печатает только HTTP-статус и доступность моделей.

Профиль стиля хранится в `chat_style`, извлечённые цитаты с источником — в `chat_facts`,
нить разговора — в `conversation_state`. Очередь `background_jobs` обрабатывается после
основной отправки и по cron. Факты: каждые 5 новых сообщений, не чаще раза в 10 минут.
Низкая уверенность маршрутизатора не меняет настройки. Разовая отправка требует кнопки.
Голосовые не распознаются. Контекст ограничивается консервативным верхним пределом
токенов по UTF-8-байтам: 4000 для команды, 6000 для ответа.

Проверенная доступная замена эмбеддингов для этого аккаунта:
`SILICONFLOW_EMBED_MODEL=Qwen/Qwen3-Embedding-0.6B` (HTTP 200, 1024 измерения).
Её нужно указать перед развёртыванием; дефолт `BAAI/bge-m3` сохранён по спецификации.
Подробные команды и ограничения проверки — в [UPGRADE.md](UPGRADE.md).

### Бесплатный режим и сбор коротких сообщений

Production использует `FREE_ONLY=true` и `PEER_DEBOUNCE_MS=4000`. Порядок провайдеров: NVIDIA Bolt → Cloudflare Workers AI → Groq GPT-OSS-20B → OpenRouter Free.
SiliconFlow полностью исключён из запросов, включая эмбеддинги и фоновые задачи,
даже если его секрет сохранён в Worker. Ручная память, стиль, история и резюме из
основного ответа остаются; фоновое извлечение фактов/состояния приостановлено.

Каждое новое текстовое сообщение собеседника переносит обработку пачки на четыре
секунды после последнего сообщения. Очередь и срок лежат в D1, отдельно для чата.
Webhook будит обработчик через `waitUntil`; cron восстанавливает работу после
прерывания Worker. Четыре секунды — окно тишины перед генерацией, не обещание
полного ответа за четыре секунды. При восстановлении после сбоя или занятой
очереди задержка может быть больше. Статус набора текста Telegram не читается.

Новые сообщения во время генерации остаются в очереди и делают старый ответ
неактуальным: он не отправляется, следующий запрос использует обновлённую историю.
Начатый запрос провайдеру уже может расходовать токены. Ручной ответ владельца
снимает ожидающую пачку, чтобы бот не отвечал поверх владельца. Команда владельца
«панда, выключи автоответчик на всех чатах» останавливает ответы немедленно без LLM.
Ограничения бесплатных провайдеров остаются; их исчерпание не обходится и дневные
счётчики при развёртывании не обнуляются.

Явное «Запомни: …» (до 400 символов) сохраняет исходный текст без вызова модели.
Разные заметки получают разные ключи; свободные просьбы по-прежнему разбирает LLM.
При уже исчерпанном внутреннем бюджете production-проба возвращает отдельный
статус `available:false`, а установка исправлений управления не отключает Worker.
Это не успешная проверка доступности модели: в отчёте печатается
`PANDA_MODEL_LIMITED`; обязательные предварительные live-тесты не пропускаются.

## Workers AI (бесплатная цепочка)

Workers AI занимает второй слот после NVIDIA. Binding `AI` работает без отдельного API-ключа.
Модель: `@cf/meta/llama-3.3-70b-instruct-fp8-fast`; другие модели требуют проверки перед добавлением в разрешённый список. Таймаут `WORKERS_AI_TIMEOUT_MS=4500`.
`WORKERS_AI_ENABLED=false` отключает канал. Внутренние ограничения `CLOUDFLARE_DAILY_TOKENS=200000`, `CLOUDFLARE_DAILY_REQUESTS=500` не являются квотой провайдера. Реальная бесплатная квота Cloudflare — 10000 нейронов на аккаунт в сутки; это не токены и не сообщения. На Workers Free после исчерпания запросы отклоняются. Платный план не включаем.
https://developers.cloudflare.com/workers-ai/platform/pricing/

Таймаут binding ограничивает ожидание ответа; уже запущенная инференс-задача может продолжить расход квоты. Фоновые SiliconFlow-задачи в FREE_ONLY по-прежнему выключены.

Workers AI: ответы `response` как объект сериализуются в JSON; поддерживаются и ответы `choices`. Для Workers AI/OpenRouter JSON задаётся инструкцией, без необязательного `response_format`; результат проверяется локально до использования. Ошибки binding показывают безопасный код Cloudflare, неизвестные ошибки не выдаются за HTTP 503.

## Незавершённые поручения владельца

`src/brain.mjs` хранит адресата, инструкцию, стадию и срок текущей задачи в `owner_tasks` (миграция 0007, 30 минут). Просьбы ответить собеседнику порождают готовый черновик из истории конкретного чата и ручных примеров за 72 часа. Уточнение по имени/username продолжает задачу, «ну» после предпросмотра не создаёт повторную отправку, «где ответ» повторно показывает существующий черновик. Стоп очищает задачу. Отправка разового сообщения остаётся за подтверждением владельца.

Служебные заметки и пустые обещания модели отклоняются; `explanation` не является готовым ответом. Автоответ со сроком разбирается без модели (до 720 минут). Разрешение адресата: текущий чат, точный username, затем совпадения имён и фамилии с проверкой неоднозначности. Поддерживаются известные формы имён и точная транслитерация, без нечёткого совпадения произвольных префиксов.

`owner-request.mjs` выполняет только конкретную текущую просьбу владельца о 12 часах для Кати, один раз и только при единственном проверенном подключённом адресате. Срок фиксируется в `owner_requests` (0008), повторный деплой не продлевает 12 часов. Переписка не выводится в CI. При отсутствии однозначного адресата настройка не применяется.


Provider deadline and response safeguards:
- `DEADLINE_EXCEEDED` means the provider request was never sent. It does not reserve a daily request; a reservation that finishes after the deadline is refunded. Attempted failures (including 400/429) still count.
- Known upstream `error.code` / `error.type` values are retained from a fixed allowlist, with no raw body, generated text, user identity or credential in diagnostics. Truncated JSON reports `finish_reason=length`.
- Assistant messages are normalized to content and function calls only before they re-enter the agent. Reasoning and arbitrary provider fields are discarded. A Workers AI `success:false` envelope cannot become a successful completion.

### NVIDIA Bolt

С `NVIDIA_ENABLED=true` и секретом Worker `NVIDIA_API` порядок в бесплатной конфигурации будет NVIDIA Bolt → Cloudflare Workers AI → Groq → OpenRouter Free. По умолчанию `NVIDIA_MODEL=nvidia/nemotron-3.5-bolt-e4b`. Для более естественных черновиков можно выбрать `google/gemma-4-31b-it` в том же слоте. NVIDIA использует таймаут 3 секунды и отдельные внутренние дневные лимиты `NVIDIA_DAILY_REQUESTS` (250) и `NVIDIA_DAILY_TOKENS` (100000). Ключ задаётся секретом, который не нужно повторно вводить при деплое.

В конфигурации Панды задано `NVIDIA_ENABLED=true`. Переменная `NVIDIA_ENABLED=false` отключает этот слот. Бесплатный Developer Program доступ NVIDIA предназначен для тестов и прототипов. Перед включением на реальном трафике проверьте право использования NVIDIA NIM в production. Закрытый `POST /ops/probe?provider=nvidia` запускает только вымышленную задачу, даже при выключенном NVIDIA в рабочей цепочке, и возвращает статус и время без текста ответа.
